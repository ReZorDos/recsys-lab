
# Рекомендательная система гаджетов

В проекте реализована рекомендательная система электронных товаров на основе характеристик гаджетов и пользовательских оценок. Используется датасет Amazon Cell Phones and Accessories (5-core), содержащий отзывы покупателей и информацию о товарах.

## Реализованные алгоритмы

Content-based Filtering — рекомендует похожие товары по названию, бренду и категории. Характеристики преобразуются в числовые признаки с помощью TF-IDF, после чего сходство товаров рассчитывается косинусной мерой. Реализация находится в `recsys/content_based.py`.

User-based Collaborative Filtering — формирует персональные рекомендации на основе пользовательских оценок. Алгоритм находит пользователей с похожими предпочтениями и рекомендует товары, которые они оценили положительно, но текущий пользователь ещё не оценивал. Для расчёта сходства также используется косинусная мера. Реализация находится в `recsys/collaborative.py`.

Popularity-based — рекомендует товары с высоким рейтингом и достаточным количеством отзывов. Для расчёта используется взвешенная средняя оценка, поэтому товары с единичными положительными отзывами не получают необоснованного преимущества. Реализация находится в `recsys/popylarity.py`.

## Установка и запуск

Рекомендуется использовать Python 3.12. После клонирования репозитория необходимо создать виртуальное окружение и установить зависимости:

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

Для подготовки данных используются архивы `reviews_Cell_Phones_and_Accessories_5.json.gz` и `meta_Cell_Phones_and_Accessories.json.gz` из [Amazon Product Data](https://snap.stanford.edu/data/web-Amazon.html). Их нужно поместить в папку `data/raw`, после чего выполнить:

```bash
python preprocess.py
python split_data.py
```

В результате будут созданы файлы `products.csv`, `ratings.csv`, `train.csv` и `test.csv`. Для запуска алгоритмов и проверки качества используются следующие команды:

```bash
python recsys/content_based.py
python recsys/collaborative.py
python recsys/popylarity.py
python evaluate.py
```

## Проблемы рекомендательных систем

Одной из основных проблем является Cold Start. Когда в интернет-магазине появляется новый пользователь, у системы ещё нет информации о его предпочтениях, поэтому Collaborative Filtering не может сформировать персональные рекомендации. Аналогичная ситуация возникает с новыми товарами, у которых пока отсутствуют оценки. Для решения можно первоначально показывать популярные товары или предлагать пользователю выбрать интересующие категории. Новые товары можно рекомендовать с помощью Content-based Filtering, поскольку он использует характеристики товара. Недостаток такого решения заключается в слабой персонализации на начальном этапе, а дополнительный опрос пользователей может усложнять взаимодействие с сервисом.

Другая проблема — разреженность данных. В крупных интернет-магазинах пользователи оценивают только небольшую часть доступных товаров, поэтому матрица оценок содержит много пропущенных значений. Из-за этого сложно находить пользователей с похожими предпочтениями. Возможным решением является использование дополнительных взаимодействий, например просмотров, покупок и добавлений в избранное, а также более сложных методов, таких как матричная факторизация. 

Также существует популярностный перекос (Popularity Bias), при котором рекомендательная система слишком часто предлагает уже известные товары, оставляя новые и менее популярные позиции без внимания. Это особенно характерно для Popularity-based. Для уменьшения перекоса можно учитывать разнообразие выдачи и включать в рекомендации менее популярные товары. Но такой подход может снизить точность, поскольку для этих товаров обычно доступно меньше пользовательских оценок.

## Проблемы использования в production

При внедрении рекомендательной системы в реальный интернет-магазин одной из главных проблем становится скорость формирования рекомендаций. С увеличением числа пользователей и товаров поиск похожих пользователей может требовать значительных вычислительных ресурсов. Для ускорения работы можно заранее рассчитывать рекомендации, использовать кэширование или более эффективные алгоритмы поиска ближайших соседей.

Не менее важна актуальность рекомендаций, поскольку предпочтения покупателей и ассортимент магазина постоянно меняются. Для решения необходимо регулярно обновлять данные и пересчитывать рекомендации, учитывая новые действия пользователей. Слишком частое обновление повышает нагрузку, а слишком редкое приводит к появлению устаревших предложений.

Ещё одна проблема связана с надёжностью системы. Если персонализированный алгоритм не смог сформировать рекомендации из-за недостатка данных или технической ошибки, пользователь всё равно должен получать предложения. Для этого можно использовать Popularity-based в качестве резервного алгоритма.

## Мониторинг и оценка эффективности

Для оценки качества рекомендательной системы используются ML-метрики Precision@K, Recall@K и Coverage. Precision показывает долю подходящих товаров среди предложенных рекомендаций, Recall — какую часть известных интересных пользователю товаров удалось найти, а Coverage — какую долю каталога система использует в рекомендациях.

Помимо ML-метрик важно оценивать влияние системы на бизнес. Основными показателями являются CTR, то есть доля показов рекомендаций, завершившихся переходом на товар, Conversion Rate — доля взаимодействий, приведших к покупке, средний чек и выручка. Предполагается, что персонализированные рекомендации помогут пользователям быстрее находить интересные устройства и повысят продажи.

Для проверки реальной эффективности можно использовать A/B-тестирование. Одной группе покупателей показываются обычные популярные товары, другой — персонализированные рекомендации, после чего сравниваются CTR, конверсия, средний чек и выручка. При этом возможна ситуация, когда персонализация увеличивает количество переходов, но практически не влияет на покупки.
